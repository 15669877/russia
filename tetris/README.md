# 极简 C 语言俄罗斯方块（纯终端）

无任何 UI 装饰，只有字符画边界 + 字符方块。所有功能模块都已真实实现：
显示、移动、边界检查、旋转、碰撞、自动下坠、锁定、消行、计分、加速、游戏结束。

**全部代码为纯 C，无 Python 依赖。**

## 六、三个关键设计点

### 1. `fits()` 是唯一真理来源

任何"能不能放这儿"的问题都问它：左右墙、地板、已有方块，全部一次性检查完。
移动、旋转、下坠、新方块生成，全走这一个函数。判定逻辑只有一份，不会漏、不会打架。

### 2. 活动方块不写进棋盘

它只存在于 `type/rot/x/y` 四个变量里。显示时临时"盖章"到缓冲区，打印完立刻擦掉。
棋盘 `board` 里存的永远是已锁定的方块 —— 这样就不存在"移动时如何在棋盘上擦除旧位置"这个问题。

### 3. 形状表用程序生成，不要手写

7 种方块 x 4 个旋转态 = 28 个状态，手写必错：
- J 和 L 会写成一样（它们是镜像关系）
- 掩码会超出该行宽度（宽度 2 的行却写了 `0x06`）
- 旋转后锚点漂移，图形会「跳一下」

`gen_shapes.c` 只手写 7 种形状的**标准姿态**，其余旋转由程序转出来，
再统一输出成 `shapes.h`（带自检：每态恰好 4 格、掩码不超宽、7 形状互异）。

**归一化**是这里最值得学的一点：每个旋转态都裁掉四周空白，只留自己的包围盒。
于是 `(x, y)` 永远表示「包围盒左上角在棋盘上的位置」，旋转时图形不会跳动。

### 4. 下坠用帧计数，不依赖定时器

主循环是忙等，每轮 `tick++`，够 `drop_interval` 就下落一格。
分数越高 `drop_interval` 越小 → 自动加速。

## 七、显示端：为什么画面不闪（render.h）

「画面一闪一闪地闪」是终端俄罗斯方块最常见的毛病，根因有三个，`render.h` 逐个解决：

| 症状 | 原因 | 解决 |
|---|---|---|
| 画面一闪一闪 | 每帧 `printf("\033[H\033[2J")` 整屏清掉再重画 | **增量渲染**：缓存每行内容，每帧只输出「和上一帧不同」的行，其余行一个字符都不动 |
| 画面整体往上飘 | 打印行数超过终端高度，终端自动滚动 | **备用屏幕缓冲区**（`\033[?1049h`）：游戏期间画在独立缓冲区，退出时原样恢复用户窗口 |
| 光标在画面里闪 | 光标停在画面上 | 游戏期间 `\033[?25l` 隐藏，退出时 `\033[?25h` 放回 |

另外两处细节：

- **棋盘高度自适应窗口**：`key.h` 里的 `term_rows()` 拿终端高度，`H = rows - 6`，
  保证打印行数永远小于窗口高度，从根上杜绝滚动。
- **一格占 2 个字符宽**（`"[]"` / `"  "`）：终端字形通常瘦高，
  一格只占 1 字符会横向拉长、看着别扭，2 字符宽正好方形对齐。

`render.h` 用法只有三个函数：

```c
r_enter();                    /* 游戏开始：进备用屏 + 藏光标 */
r_frame_start();              /* 每帧开头 */
r_line(行号, "内容");          /* 写第 N 行（0 起算），没变就不输出 */
r_leave();                    /* 游戏结束：恢复光标 + 切回原屏 */
```
